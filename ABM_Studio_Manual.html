v1.0ABM Studio User Manual

A Browser-Based Agent-Based Modeling Environment

1What is ABM Studio?

ABM Studio is an agent-based model (ABM) modeling environment that runs entirely in your browser. No installation, no account registration: just double-click the file to launch it.

The model code is written in JavaScript, and the intended workflow is to hand a specification to a generative AI to generate the code, then paste it in as-is and run it. Even without programming experience, you can customize and observe various complex-systems models on the spot.

The idea behind this tool Recent advances in generative AI are reshaping the "understanding by building" (constructive) style of modeling in complex systems and artificial life. By giving a prompt with just the skeleton of an idea, not a complete specification, you can auto-generate a wide variety of models, have the AI explain them when you want to understand them, and refine ideas through dialogue. Letting the AI generate everything, however, tends to produce wildly inconsistent results.
ALifeCoreStudio (the three studios, ABM / EVO / IEC) keeps a common framework for model construction, visualization, and analysis fixed and lets generative AI produce only the essential parts of a model. It is intended for beginners with no programming experience giving free form to their ideas, students growing models together with AI, and researchers building prototypes quickly. By making it easy to generate possible models freely within a shared framework, it aims to accelerate the constructive approach to scientific understanding and to spread the joy of imagining and running "what worlds could be."
Key point ABM Studio comes with the major models covered in coursework built in (ECA, Game of Life, Schelling segregation, Boids, ant pheromones, Prisoner's Dilemma). Start by running these.

What you can do:

You can render a model in real time on a canvas, change parameters with sliders and see the effect immediately, record graphs (time series), save the results of multiple runs with different parameters and overlay them on a graph to compare conditions, save field images or record video, export data as CSV files, save and reload the model you built as a .js file, convert a model into a Python script, and rewrite the code to build a new model.

What you cannot do: internet access, loading large databases, 3D rendering, and sharing data between multiple windows are not supported.

Role of Each Part

The header shows the current tick count, the FPS (frame rate) while running, and the run state (RUNNING / LOOP / STOPPED). ❔ Help lets you check the key points of operation at any time, and ⟳ Initialize resets the model.

The left area (canvas) is the heart of the model. The movement of agents, changes in grid colors, pattern growth, and so on are rendered here. Below it are the playback controls and sliders for speed, max tick, and draw skip.

The right area holds the controls that govern the model. Changing a parameter with a slider is reflected immediately in the running model in "Apply Immediately" mode (see §5 for details). You can also save experiments and overlay them on the graph to compare conditions (§6).

The code bar (bottom of the screen) is the area for entering and managing code. It's normally collapsed. Clicking ▸ Code expands it, revealing a code field with line numbers. If there's an error, the offending line and a hint are shown below it.

4Running & Observing

Run Controls

Press ▶ Run to start the model. Press again to pause. Press ⏭ 1 tick to advance a single step while staying paused, which is handy when you want to follow changes slowly. Press ⟳ Initialize to start the model over from the beginning, using the preset selected in the right panel and the current parameter values.

Speed Slider

The "Run Speed" slider sets how many steps (ticks) advance per frame. Higher values run faster but draw more coarsely. For models like ECA where you want to carefully watch changes over time, set it to 1 t/f so you can observe rows being built up one at a time.

Draw Skip and FPS

The "Draw Skip" slider sets how often the screen is redrawn (once every 1/2, 1/4 frames, etc.). Computation (step) still advances every frame and only drawing is reduced, which is useful when you want to run a heavy model with many agents at high speed. Computed results (graphs, state) are still recorded correctly even when drawing is skipped.

The — fps display in the header shows the number of draws per second (frame rate) while running. If this drops significantly, try raising draw skip, lowering the speed, or reducing the number of agents.

Max Tick and Behavior on Reaching It

The "Max Tick" slider sets the ending tick. Turning on the toggle to its right shows a selector for choosing the behavior when the max tick is reached. The default is "⏹ Stop only," which pauses in place without reinitializing (it does not go back to the start). Switching to "🔁 Loop" makes it automatically reset and repeat once the max tick is reached, which is useful when you want to repeatedly observe long-term self-organization or a steady state. Turning the toggle off ignores the max tick and lets the model keep running indefinitely.

Stop Conditions

Some models have stop conditions defined, such as "stop when everyone is happy" or "stop when the number of infected reaches 0." You can turn this ON/OFF with the stop-condition toggle in the right panel. When the stop condition is met, the "■ STOPPED" badge lights up and a toast shows how many ticks it took to stop.

Initial-State Presets

Many models come with several initial-state presets (e.g., "Random," "Glider Gun," "Pulsar" for the Game of Life). Clicking a preset button in the right panel resets the model to that initial state. After choosing a preset, adjust parameters as needed and then click "⟳ Initialize."

Command Buttons

Some models have "command buttons" in the right panel that you can press even while running (e.g., "Clear Pheromones," "Add One Glider," "Add Defector at Center"). You can perturb the model without stopping it, and observe how it responds.

5Changing Parameters

Sliders are arranged in the "Parameters" section of the right panel. Moving a slider changes the value immediately. You can choose the behavior on change between "Apply Immediately" and "Auto-Reinitialize" (the switch just above the parameters).

ModeBehavior
Apply Immediately (default)Moving a slider is reflected in the running model right away. Existing history (graphs) is not cleared.
Auto-ReinitializeEvery time you move a slider, the initial state is automatically rebuilt (history is reset). Useful when you want to see the effect of changing initial conditions repeatedly.
About the "Initialization needed" hint Values that are used only at initial placement, such as density or initial population, are not reflected in the result even if changed while running. If you change such a value in Apply Immediately mode, a "⟳ Initialization needed" hint appears below the parameter field. Press Initialize Now or ⟳ Initialize to apply it. History is never cleared automatically.

When a ⓘ icon appears next to a parameter name, hovering over it shows an explanation of its meaning and effect (models whose code has help written into PARAM_DEFS). Some representative parameter examples are shown below.

6Saving & Comparing Results

Saving and Comparing Experiments

The "Save/Compare Experiments" section in the right panel lets you compare the results of multiple runs with different parameters side by side. After running for a while, press 📸 Save Snapshot to save the graph and full parameter set at that moment; from then on it's overlaid on the graph as a colored dashed line. Change conditions and run again, and the difference from the previous run is visible at a glance.

For saved experiments, toggle visibility with the 👁 icon at the start of the row, and delete with ✕. Each row shows the parameters at that time, so you can tell which result belongs to which condition. 🗑 Clear removes everything.

Using this in a presentation Run scenario A → 📸 Save Snapshot → change parameters and run scenario B, and the graphs for A and B are shown overlaid. You can show live "what happens if you only change the parameters of the same model."

Copying and Saving Field Images

The 📋 Copy button below the left area copies the canvas image to the clipboard, so it can be pasted directly into slides or Word. Press ⬇ Save to download it as a PNG file. The filename includes the current tick count.

Saving Graphs and CSV Export

Each graph has the following buttons in its top-right corner.

💾Saves the time-series data as a CSV file. Data from saved experiments is exported along with it. Includes a BOM so it doesn't garble.

Pressing ⬇ Save CSV in the "Save/Compare Experiments" section exports all graphs and saved experiments together into a single CSV file, which is useful when you want to analyze multiple conditions together in spreadsheet software.

Live and time-shift playback

Record states in "Save and compare experiments" is on by default on a computer, so a timeline sits under the run buttons from the start and anything you notice while the run is going can be revisited. On phones and tablets it starts off, because recording is the most memory-hungry part of a run and those devices have the least to spare; tick the box there whenever you do want the timeline. The run seed is drawn afresh on every initialization and cannot be typed back in, so a run that was not recorded cannot be recovered. Recording stops on its own at the limit set beside the box. LIVE is checked by default and the display follows the newest step. Drag the bar, or uncheck LIVE, and you can go back to any recorded step while the run continues in the background, the same idea as the seek bar on a live video.

  • ▶ plays the recorded steps back at 12 frames per second, and stops when it catches up with the run.
  • The position readout shows where you are within what has been recorded, as in "step 45 / 120". The number on the right keeps growing as the run continues.
  • An amber marker on each chart shows where the frame you are viewing sits in the time series.
  • Re-checking LIVE returns the display to the newest step.

The granularity you can seek to is the recording interval (with "every 5 steps", you land on multiples of five). How far back you can go is set by the limit next to the interval: 500 MB by default, and no limit is available (recording then continues until the browser runs out of memory). The readout reports how much has been recorded, so the limit can be raised before it is reached.

Reproducing each step, and viewer replay

So you can reproduce the state at each step later, the ZIP carries two mechanisms:

  • Method A (deterministic seed): during a run the engine seeds the randomness and records the seed in settings.seed. The exact run can be reproduced from model.js + settings + seed (this works for AI-modified or newly-created models too).
  • Method B (recorded state): turn on Record states (for replay) in "Save/Compare Experiments" before running, and each step's state is saved to frames.jsonl (you can also choose the interval). Leave it off when you are only observing; the run is faster that way.

Drop the exported ZIP onto the bundled ALifeCoreStudio_Viewer.html to replay each recorded step along a timeline (play/pause, scrub, speed), rendered by the model's own drawing code. It works for built-in models as well as modified or newly-created ones.

Manual Range Settings for Graph Axes

Pressing ⚙ Axes in the top-right of each graph opens range-setting fields for the vertical (Y) and horizontal (X, tick) axes.

ModeBehavior
Auto-scale (default)As before, the axis min/max are determined automatically based on the range of recorded data.

Saving and Loading Model Files

Pressing 💾 Save .js in the code bar saves the model currently in the code field as a .js file. 📂 Open loads a saved .js / .txt file and applies it directly. This lets you reuse a model you've built later, or submit and share it.

💾 HTML Export

Pressing 💾 HTML Export in the code bar exports a standalone HTML file that runs only the currently running model as-is. It doesn't include the code-editing area or generative-AI-related UI such as ✨/✏️/🤖: just a simple screen with the model's display, control panel, and graphs. Double-clicking it runs the model (with no internet connection needed), making it handy for distribution or as a coursework/presentation submission.

How it works and things to note What gets exported is a single HTML file with "the code currently in the code field" embedded as-is. Internally it uses the same engine as ABM Studio itself, so parameter adjustment, graphs, recording, and other features work the same way. Switching to a different model in the code bar afterward has no effect on the file you've already exported.

Video Recording (Choice of Format)

The menu next to the record button lets you choose the output format from MP4 / WebM / Auto. Press ⏺ Record to start recording, and the "● REC" badge blinks. Press ⏹ Stop again to end recording, and the file downloads.

Choosing a format In most environments, MP4 is recommended since it plays easily in PowerPoint and various players. The MP4 is written as H.264, which QuickTime Player, PowerPoint, and Keynote all open directly. If the browser cannot record H.264, the file is saved as WebM instead (with a toast notification); WebM plays in browsers and VLC, but not in QuickTime Player.
Tip Field images (PNG) or graph images are handy for presentation materials, and CSV data (comparing multiple conditions) is handy for reports. Video is useful for live demos during a presentation.

7Generating Code with AI

Model code for ABM Studio can be generated by handing a specification and instructions to a generative AI (even the free tier works). Pressing the ✨ New Model Prompt button in the code bar copies a prompt, complete with the necessary specification, to the clipboard.

1
Press the "✨ New Model Prompt" button Found in the code bar (bottom of the screen). A "New model prompt copied" toast is shown.
2
Open a generative AI and paste the prompt Paste it into a new chat with WinCtrl+V/Mac⌘+V.
3
Rewrite the "[Model to Implement]" field and send it Change the part in the prompt that says "(Rewrite this: e.g., 'Reynolds' Boids flocking model')" to the name of the model you want to build, then send it.
4
Copy the generated code The generative AI returns a code block (```javascript ... ```). Use the "Copy" button in the top-right of the code block to copy the code.
Example prompt Writing a specific model name and parameter requests in the "Model to Implement" field improves accuracy. For example, writing something like "Wolf-Sheep predator-prey model (Moore neighborhood, wolves die if they don't eat)" tends to produce more faithful code.
Note on free-tier generative AI Free-tier GPT-3.5/4o may skip over part of a long specification. If you get an error, try re-instructing it with: "Please fix this according to the specification, observing the following prohibitions: no document.*, no import/export, no class keyword."
About the built-in prompts In addition to the rules on disallowed syntax, the ✨ New Model Prompt / ✏️ Modify Prompt already include instructions to "add help (an explanation) to parameters" and "add a brief explanatory comment about the model at the end." This makes it easier to see what model the output code is and what was changed. Being as specific as possible about what you want to change in the initial request improves accuracy.

🤖 AI Generate: Connecting Directly to a Generative AI API (LM Studio / Cloud)

Pressing 🤖 AI Generate in the code bar lets you connect directly to an OpenAI-compatible API to perform modification or creation. The returned code is automatically inserted into the code field, so no copy-and-paste is needed (it isn't run until you press ▶ Apply).

  • Local (LM Studio, etc.): load a model, start the local server, and turn "Enable CORS" ON in the server settings. The endpoint is http://localhost:1234 (no API key needed).
  • Cloud (OpenAI-compatible): enter the endpoint and API key. Examples: OpenRouter https://openrouter.ai/api/v1, DeepInfra https://api.deepinfra.com/v1/openai, OpenAI https://api.openai.com/v1. Most are pay-as-you-go.
  • You can choose the model name via 🔄 Fetch List (manual entry also works). Settings are remembered in the browser.
When the connection doesn't work "Failed to fetch" is usually caused by the server not running, CORS not being enabled, or a wrong URL. First try opening http://localhost:1234/v1/models directly in your browser to check whether JSON is returned. For cloud services, the service itself must support CORS (OpenRouter and DeepInfra do).

🐍 Python Prompt (Also Generates requirements.txt, v1.0)

Pressing 🐍 Python Prompt in the code bar copies a prompt to the clipboard that converts the model currently in the code field into a standalone, runnable Python script (using matplotlib) and a requirements.txt. There's nothing to edit: just paste it into a generative AI and send it as-is.

  • The generative AI's reply is instructed to come back as two code blocks: ```python ... ``` and ```text ... ``` (the contents of requirements.txt).
  • The original code's setup / step / draw are mapped to the Python side's initialization, update, and matplotlib drawing functions respectively, with the correspondence indicated in comments.
  • When PARAM_DEFS (parameters) and PLOT_DEFS (graphs) are present, they are carried over to the Python side as variable definitions and time-series recording.
  • To run it locally, save the two code blocks as model.py and requirements.txt respectively, then run pip install -r requirements.txt followed by python model.py.
Use case Use this when you want to go beyond browser-based observation and do numerical analysis or make figures for a report in Python (numpy, matplotlib, pandas, etc.). What the generative AI outputs varies depending on the model's complexity, so it's a good idea to review the code before running it.

9Modifying Code

If you want to change parameters or behavior based on a running model, use the ✏️ Modify Prompt button. This copies the entire current code together with a modification-instruction template.

Pressing 📖 Explain Prompt copies a prompt asking the AI to explain what kind of model the currently running code is (requesting an overview, an explanation of the algorithm, and pseudocode). Pasting it into a generative AI produces an explanation faithful to the implementation. Also, including const TITLE = 'Model Name' in generated or modified code is reflected in the browser tab name, the "Model Overview" heading, and the filename used by 💾 Save .js (e.g., SegregationModel.js).

Techniques to reduce failures, even on the free tier The prompts keep the specification to a minimum and strongly instruct, at both the beginning and end, to "output only one code block, in full, without omission" (to reduce truncated output and mixed-in explanatory text on the free tier and with smaller models). In the ✏️ Modify Prompt, the [What to Change] section is placed at the end, so list your changes there as bullet points.

ECA (Wolfram's 1D Cellular Automaton)

CA

A one-dimensional cellular automaton. Each cell applies a rule based on the state of its left and right neighbors to determine its state on the next row. Time evolution is displayed stacked vertically, so the canvas becomes a "spacetime diagram in which time proceeds downward."

Setting the speed slider to 1 t/f is strongly recommended. Watching each row being drawn one at a time makes it visually clear which rule produces which pattern.

Example rule numbers worth observing: rule 28, which produces a regular pattern (class 1); rule 90, a periodic pattern (class 2); rule 30, a complex (chaotic) pattern (class 3); and rule 110, said to have computational universality (class 4). The rule number is displayed in the top-left of the canvas.

Classroom exercise idea An effective exercise is to have each student find one pattern corresponding to each of the four classes by changing the rule number, starting from the same initial state (a single ON cell in the center).

Game of Life (Conway's Life)

CA

A classic two-dimensional cellular automaton. The rule consists of only two conditions: "a living cell survives if it has 2 or 3 living neighbors, and a dead cell is born if it has exactly 3." Yet this produces a surprisingly rich variety of patterns (still lifes, oscillators, gliders).

The "Glider Gun" preset is Gosper's glider gun (1970), which keeps producing gliders periodically. The "Pulsar" preset is a symmetric pattern that oscillates with period 3. Trying the initial-density slider in the range 0.1–0.5 reveals phase-transition-like changes in behavior.

Schelling Segregation Model

ABM

Two types of agents (blue and red) live on a grid, following the rule that "an agent becomes unhappy and moves if fewer than a certain fraction of its neighbors share its own color." Remarkably, strong residential segregation emerges even at a low happiness threshold (e.g., 30%).

The stop condition "stop when everyone is happy" is set, so you can see how many ticks it took to stabilize. Comparing a happiness threshold of 0.30 versus 0.70 shows that stronger segregation occurs faster.

Flocking (Reynolds' Boids)

ABM

Reynolds' (1987) Boids model. Three purely local rules, separation (avoid crowding neighbors), alignment (steer toward the average heading of neighbors), and cohesion (steer toward the average position of neighbors), are enough to produce emergent alignment reminiscent of a flock of birds or a school of fish.

The alignment index φ (order parameter) shown on the graph is 0 for disorder and 1 for perfect alignment. Press "Scatter All" and observe the process by which φ rises. The balance among the three spatial scales, separation radius, alignment radius, and cohesion radius, determines the shape of the flock.

Ant Pheromone Model (Ant-pheromone)

ABM

A foraging-behavior model in which ants discover a path to a food source using pheromones (referred to in this tool as Ant-pheromone. It covers the same subject as NetLogo's "Ants," but the homing mechanism, the diffusion/evaporation formulas, and the parameter set are an independent implementation; none of NetLogo's code is used). When an ant finds food, it lays down pheromone while returning to the nest. Other ants head toward higher pheromone concentrations, gradually reinforcing an efficient path. This is the very natural phenomenon that inspired ACO (Ant Colony Optimization) algorithms.

On the canvas, the white area is the nest, the green area is the food source, and the blue trail marks paths with high pheromone concentration. Pressing "Clear Pheromones" resets the pheromone memory, sending the ants back into exploration mode. A higher evaporation rate makes paths harder to maintain.

Spatial Prisoner's Dilemma (Nowak & May 1992)

ABM

Each agent on the grid chooses to be a cooperator (C, blue) or a defector (D, red) and plays a game against every neighbor in its Moore neighborhood. Mutual cooperation earns +1, a defector exploiting a cooperator earns +b (b > 1), and mutual defection earns 0. Each step, every agent copies the strategy of whichever neighbor scored highest.

Small changes in the defection payoff b produce dramatic differences: cooperators can go extinct, beautiful spatial patterns (fractal-like clusters) can appear, or cooperation and defection can coexist. The most effective way to observe this is to slowly raise b between 1.5 and 2.0 while watching the cooperation-rate graph.

SPS (Social Particle Swarm)

ABM

An original model developed by this project's author group, in which particles are treated as "individuals," and both a cooperate(C)/defect(D) strategy and "distance = relationship strength" evolve simultaneously (Nishimoto, Suzuki, & Arita, 2023, Psychologia). Each particle has its own "propensity to cooperate" (threshold ct), and decides its next strategy by comparing its threshold against the fraction of cooperators among neighbors within interaction radius R (the higher the neighborhood cooperation rate, the more likely the particle itself is to cooperate, a generalized tit-for-tat).

Movement is determined by moving at a constant speed v in the direction of the resultant force, where the payoff from each neighboring interaction (mutual cooperation: +1, mutual defection: -1, the exploiter's side: temptation to defect Tem, the exploited side: sucker's payoff Suc) is weighted by the inverse square of distance. In other words, particles are drawn toward partners with a good relationship (positive payoff) and move away from partners with a bad relationship (negative payoff). From this simple rule, a periodic pattern can emerge: "a cooperation cluster forms → defectors invade → the cluster collapses and disperses again."

Increasing the temptation to defect Tem makes it easier for defectors to invade a cluster, while decreasing (making more negative) the sucker's payoff Suc makes cooperators more likely to flee and disperse. The perturbation probability pd is the chance that a strategy flips randomly each step; periodic collapse can occur even when this is set to 0. It's instructive to compare the "Random placement (diverse ct)" initial-state preset, which tends to show a clear collapse cycle, against "Uniform ct = 0.5 (no diversity)," which tends to produce a relatively stable cooperation cluster.

Classroom exercise idea Observe the two graphs "fraction of cooperators" and "mean neighbor count (an indicator of aggregation and dispersion)" side by side. You can trace the cycle on the graphs themselves: mean neighbor count rises (aggregation) → cooperation rate falls (defectors invade) → mean neighbor count drops sharply (collapse) → re-aggregation. Please cite the paper above if referencing this model in research.

10Errors and Solutions

If an error occurs when you press "▶ Apply" or while running, a red error message appears in the code bar. The line number of the cause, the content of that line, and a beginner-friendly hint are shown in plain language, and the code field opens automatically. Disallowed syntax such as class, document.*, and fetch is detected before applying, and guidance on "what isn't allowed and how to fix it" is shown. See the table below as well.

11Frequently Asked Questions

Q. I pasted code and the sliders in the right panel disappeared.
A. If PARAM_DEFS is not defined in the new code, sliders are not shown. If you need parameters, ask the generative AI to "add PARAM_DEFS."

Q. The graph isn't showing.
A. If PLOT_DEFS is not defined in the code, no graph is shown. Ask the generative AI to "add a graph via PLOT_DEFS."

Q. My code disappears when I close the browser.
A. ABM Studio does not auto-save code. You can save the current model as a .js file using 💾 Save .js in the code bar. Load it next time with 📂 Open to continue right where you left off (keeping it in your generative AI chat history is also a good backup).

Q. Nothing happens when I press the "📋 Copy" button (a warning says HTTPS is required).
A. Clipboard access requires an HTTPS environment. If you're opening the file locally, the copy function may not be available. Use the "⬇ Save" button to save it as a file instead.

Q. The CSV data I copied from a graph is garbled.
A. When pasting into Excel via the clipboard (⬇ CSV), use the "Import Text" feature and select UTF-8. The 💾 (save CSV file) and ⬇ Save CSV features save with a BOM, so opening them directly in Excel doesn't garble. Both load into Google Sheets without any issue.

Q. I want to compare multiple results with different parameters.
A. Use "Save/Compare Experiments" in the right panel. Run for a bit, then press 📸 Save Snapshot to have it overlaid on the graph. Change conditions and run again to compare with the previous run (§6). To gather all conditions into a spreadsheet, use ⬇ Save CSV to export everything into one file.

Q. Increasing the number of agents makes things heavy.
A. Raising the "Draw Skip" slider at the bottom left (e.g., to 1/4) speeds things up by leaving computation as-is and only reducing drawing. Check the FPS display in the header to confirm the effect. Lowering the speed slider also helps (§4).

Q. In some environments the recorded video won't play.
A. You can choose MP4 from the menu next to the record button, which plays more easily in most players and PowerPoint. On browsers that don't support MP4, it's automatically saved as WebM instead (§6).

Q. I don't understand what this parameter does.
A. If there's a ⓘ icon next to the parameter name, hovering over it shows an explanation. If there isn't one, ask the generative AI to "add help (an explanation) to PARAM_DEFS" and it will appear from then on.

Q. ECA scrolls by so fast I can't see it.
A. Lower the speed slider down to 1 t/f. In ECA, 1 step = 1 row, so at high speed the rows stack up quickly and appear to stream by.

Q. The code generated by the AI seems too long to fit in the code area.
A. The code area is scrollable, so any length is fine. Select all with WinCtrl+A/Mac⌘+A before pasting.

Q. I want to look at a built-in model's code as a reference.
A. After selecting a model and pressing "▶ Apply," click "▸ Code" to display that model's code in the code area. You're free to read or modify it. Pressing the 📋 Copy Spec button copies the specification together with the current code, ready to hand to a generative AI.
