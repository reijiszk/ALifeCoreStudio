🤔 What is ABM Studio?

ABM Studio is a tool for building "models (experiments)" that run in your browser. No installation needed: just double-click the file to use it. It works not only on PCs but also on smartphones and tablets, with the screen automatically adjusting.

An agent-based model (ABM) is a model (experiment) in which "many individuals (agents) each move according to simple rules." Flocking, epidemic spread, social segregation: in every case, surprisingly complex phenomena emerge purely from individual-level rules.

Normally this would require programming, but with ABM Studio you can run models you're interested in simply by having generative AI write the code and pasting it in.

The idea behind this tool Recent advances in generative AI are reshaping the "understanding by building" (constructive) style of modeling in complex systems and artificial life. By giving a prompt with just the skeleton of an idea, not a complete specification, you can auto-generate a wide variety of models, have the AI explain them when you want to understand them, and refine ideas through dialogue. The catch is that letting the AI generate everything tends to produce wildly inconsistent results.
ALifeCoreStudio (the three studios, ABM / EVO / IEC) keeps a common framework for model construction, visualization, and analysis fixed, and lets generative AI produce only the essential parts of a model. This supports beginners with no programming experience giving free form to their ideas, students growing models together with AI, and researchers building prototypes quickly. By making it easy to generate possible models freely within a shared framework, we hope to accelerate the constructive approach to scientific understanding and spread the joy of imagining and running "what worlds could be."
All you need A browser with the ABM Studio HTML file open, plus a generative AI service (ChatGPT, Gemini, Claude, etc.; the free tier is sufficient)
Difference from EVO Studio ABM Studio is a tool for observing how phenomena emerge from individual-level rules. EVO Studio is a tool for searching for good answers through evolution. In ABM, the most important thing is deciding the three elements: agents, environment, and interaction.

▶️ First, Try Running a Built-in Model

ABM Studio comes with models built in. Let's try running one first.

1
Choose a model

Select a model from the dropdown ("── Select a Model ──") in the code bar at the bottom of the screen. Clicking it sets everything up automatically.

2
Press ▶ Run

The model (experiment) starts moving on the canvas. Press again to pause. Move the sliders in the right panel to change parameters in real time.

Recommended way to explore First run "Flocking" and try moving each of the three weights (0–6) for separation, alignment, and cohesion one at a time. Increasing alignment brings the alignment index φ in the top-left of the screen closer to 1; increasing cohesion causes clustering; and increasing separation causes spacing to widen. You'll understand "which rule affects what" without reading any code.
Handy features to know about
  • Model overview: at the top of the right panel, you'll see explanations of the agents, environment, and interaction. Reading this before running helps you understand faster.
  • Direct numeric input: in the number field to the right of each slider, you can type an exact value from the keyboard.
  • Observe slowly: the speed slider can be set very slow, letting you follow it one step at a time (handy for ECA, one row at a time).
  • Quantify with graphs: a graph tracking state counts over time (e.g., S/I/R populations for SIR, number of ON cells for ECA) lets you verify the phenomenon.
  • Compare results: use 📸 Save Snapshot to overlay results on the graph for A/B comparison. Use ⬇ Save CSV to export for Excel.
  • 📦 Download ZIP: the 📦 Download ZIP button in "Save/Compare Experiments" bundles all data since initialization into a ZIP. It contains metadata.json (the experiment settings: parameters, initial state, stop condition, random seed, etc.), one .csv per graph, data.json (all data), and the model code itself model.js. Handy for analyzing later or reproducing the same experiment.
    Turn on Record states (time-shift / replay) before running and each step's state is saved to frames.jsonl (leave it off when just observing, which is faster). Drop the exported ZIP onto the bundled ALifeCoreStudio_Viewer.html to replay each recorded step with the model's own drawing (built-in, modified, or new models all work).
  • Watch it back while it runs: once states are being recorded, a timeline appears under the run buttons. LIVE is checked by default and the field follows the newest step. Drag the bar (or uncheck LIVE) to go back to any earlier step while the run continues in the background, like the seek bar on a live video. ▶ plays the recorded steps back, an amber marker on each graph shows where you are, and re-checking LIVE returns you to the newest step. How far back you can go is set by limit next to the interval (500 MB by default, up to no limit).
  • When it's heavy: raising "Draw Skip" to something like 1/4 lightens the load. Also make use of ❔ Help and the ⓘ icon next to each parameter.
  • 💾 HTML export: a button in the code bar lets you export the currently running model as a standalone HTML file that runs that model alone. It comes with a simple screen with no editing UI, making it ideal for saving to distribute, submit, or present.

Cooperation/defection and "distance = relationship" co-evolve, including cycles of gathering and collapse.

👁️ Reading the Screen (Overview, Graph, Speed)

Checking the following four areas, before and after running, will greatly deepen your understanding.

1
Model overview

At the very top of the right panel, you'll see explanations of the agents (what moves), environment, and interaction. Start by reading this.

2
Parameters (sliders + numeric input)

In addition to using the sliders, you can type an exact value into the number field on the right (e.g., rule number 110). The ⓘ icon next to it explains what it means.

3
Speed (slow to fast)

The speed slider can be set very slow, which is useful for following changes one step at a time.

4
Graph (state counts over time)

Most models come with a time-series graph. Use the numerical trends to quantitatively verify the phenomenon, and use 📸 Save Snapshot to compare conditions. Clicking ⚙ Axes in the top-right of the graph lets you choose whether the vertical/horizontal axis ranges stay "auto-scaled" or are set manually by specifying min/max.

✏️ Modify a Running Model (Start Here First)

This is the easiest entry point. Making small changes to a built-in model lets you tailor it to your own interests. Pressing the "✏️ Modify Prompt" button copies the current code together with modification instructions, which is more reliable than writing from scratch.

📖 Explain Prompt and Model Names If you want to know how the currently running model "works," press 📖 Explain Prompt. This copies an explanation request that includes the current code, so pasting it into a generative AI gives you a detailed walkthrough covering the overview, an explanation of the algorithm, and pseudocode. Also, generated or modified code includes const TITLE = 'Model Name', which is reflected in the browser tab name, the "Overview" heading, and the filename used by 💾 Save .js (e.g., SegregationModel.js).
1
Press "✏️ Modify Prompt"

Found in the code bar. The current code is automatically included in the prompt.

2
Paste into generative AI and describe what you want to change

In the [What to Change] section at the end of the pasted prompt, list what you want to change as bullet points, 1–2 items at a time.

3
Replace all of the returned code

Select all in the code field (Ctrl+A), paste (Ctrl+V), and press "▶ Apply".

Example Modification Requests by Model (2 Each) 💬

Base ModelIdeas for modification requests to the generative AI
📏 ECA
  • Instead of a rule number, let me specify the output for each of the 8 neighborhood patterns (111–000) using 8 individual ON/OFF switches.
  • Extend the state to three values (0/1/2) and display each in a different color.
🔲 Game of Life
  • Let me change the neighbor-count conditions for "birth" and "survival" with sliders (e.g., B36/S23).
  • Gradually darken each cell's color based on its "age" (how many generations it has stayed alive), so long-lived stable structures are visible at a glance.
🏘 Segregation
  • Increase the number of resident types to three, each shown in a different color.
  • Make the satisfaction threshold (tolerance) a separate slider for each type, so I can compare how segregation progresses.
🐦 Flocking
  • Add one predator that chases agents when they come within a certain distance, and make the predator's speed a slider.
  • Place circular obstacles on the screen that agents avoid, with the radius controlled by a slider.
🐜 Ants
  • Increase the number of nests to two, so I can watch which of the two colonies collects more food in a competition.
  • Split the pheromone into two kinds, "returning to nest" and "searching for food," and display them in different colors.
🤝 Prisoner's Dilemma
  • Let me toggle the imitation neighborhood between "4-neighbor" and "8-neighbor," so I can compare how the shape of cooperation clusters changes.
  • Highlight only the cells whose strategy changed from the previous generation, so the "battle line" between cooperation and defection becomes visible.
🦠 SIR
  • Add initially vaccinated (immune) individuals, plus a vaccination-rate slider (0–1).
  • Turn it into an SIRS model where recovered individuals gradually lose immunity and can be reinfected, with an immunity-loss-rate slider.
⚪ SPS
  • Leave a short trailing trail behind each moving particle, so the flow of clustering and scattering can be followed visually.
  • Count and display the current number of "clusters" on screen, so the repeated cycle of aggregation (count decreasing) and collapse (count increasing) can be tracked numerically.
Tips for modification Trying to change too much at once tends to fail. It's best to request small changes, 1–2 at a time, and check that it works after each one.

✨ Have Generative AI Create a New Model

Once you're comfortable modifying models, you can also build a brand-new model from scratch. Pressing the "✨ New Model Prompt" button copies a specification to hand to the generative AI onto your clipboard.

1
Press "✨ New Model Prompt"

Found in the code bar at the bottom of the screen. If you see "Copied," you're good to go.

2
Paste into generative AI and edit it

Paste it into the generative AI's chat field, rewrite the [Model to Implement] section to describe the model you want to build, and send it.

3
Copy the code and paste it into ABM Studio

Copy only the contents of the code block (```javascript ... ```) that the generative AI produced, paste it into the code field, and press "▶ Apply".

Phrasing Your Request So It Comes Across Clearly 💬

In ABM, the key is to convey "who (the agents), in what environment, and how they interact."

🙋
Example student input
Build a model where an infectious disease spreads and recovered people become immune.
Let me change the infection probability and recovery probability with sliders, and also show a time-series graph of the number of infected people.
🙋
Example student input
Build a traffic model where car agents move on a grid and stop at red lights.
I want the signal interval and car density to be parameters, and I want to see how congestion builds up.
📋 Example Request to Generative AI (content to write in the [Model to Implement] field)
Please build a model about theme (e.g., epidemic, traffic, ecosystem).

The agents are what kind of individuals (e.g., people, cars, birds),
the environment is what kind of space (e.g., grid, toroidal plane, with obstacles),
and the interaction is what they do (e.g., avoid nearby others, infect on contact, follow pheromones).

Parameters I want to change with sliders: e.g., population, infection probability, speed
What I want to see on the graph: e.g., number of infected over time, cooperation rate (omit if none)

🐍 Convert Code to Python (with requirements.txt)

When you want to convert an ABM Studio JavaScript model into a Python script you can use directly in a report or research, use the "🐍 Python Prompt" button, found in the code bar.

1
Press "🐍 Python Prompt"

The contents of the model currently in the code field are automatically included in the prompt.

2
Paste into generative AI and send it

Just paste it as-is; there's nothing you need to edit.

3
Save the two code blocks

The generative AI returns two code blocks: a Python script and a requirements.txt. Save them as model.py and requirements.txt respectively, in the same folder.

4
Run it in your local environment

In a terminal, run pip install -r requirements.txt, then python model.py, and the same model will run in a matplotlib window.

When this is handy This is useful when you want to move past browser-based observation and do careful numerical computation, statistical analysis, or figure-making for papers and reports in Python (numpy, matplotlib, pandas, etc.). The explanations you wrote in ABM Studio's "Overview" field and the meaning of each parameter (help) are also carried over as comments during conversion.

🤖 Connect Directly to a Generative AI API (Local / Cloud)

Instead of copying and pasting to a generative AI, you can also connect directly to an LLM running on your own PC (such as LM Studio) and complete both modification and creation entirely within Studio. This saves you the trouble of pasting code back and forth, and lets you run everything locally without sending anything over the network. Any OpenAI-compatible API works (LM Studio, Ollama, OpenAI, etc.).

What you need An OpenAI-compatible server such as LM Studio (free). Load one model and start the local server.
1
Start the server in LM Studio

Load a model → click Start on "Local Server." Make sure to turn "Enable CORS" ON in Server Settings (this is required for connecting from a browser).

2
Press "🤖 AI Generate"

Found in the code bar at the bottom of the screen. A settings panel opens, where you check the endpoint (default http://localhost:1234) and the model name. You can choose a model name via 🔄 Fetch List. Settings are remembered, so you won't need to do this again next time.

3
Choose "Modify / Create New," write your instructions, and press ▶ Send

Choose either "✏️ Modify Existing Code" or "✨ Create New," write what you want, and send. The generated code is automatically placed in the code field. Review it and press ▶ Apply to run it.

When the connection doesn't work "Failed to fetch" is usually caused by the server not running, CORS not being enabled, or a wrong URL. First try opening http://localhost:1234/v1/models directly in your browser and check whether JSON is returned. If it is, LM Studio is working correctly. You can also type the model name manually.

Using Cloud Generative AI Services (OpenRouter, DeepInfra, OpenAI, etc.)

Beyond local models, you can also use OpenAI-compatible cloud APIs from the same panel. You don't need to run your own server: just enter each service's base URL as the "Endpoint," your issued key as the "API Key," and the model name.

ServiceEndpoint (Base URL)Example model names
OpenRouterhttps://openrouter.ai/api/v1openai/gpt-4o-mini, deepseek/deepseek-chat, etc.
DeepInfrahttps://api.deepinfra.com/v1/openaimeta-llama/Meta-Llama-3.1-8B-Instruct, etc.
OpenAIhttps://api.openai.com/v1gpt-4o-mini, etc.
Note on cloud usage These all require an API key, and most are pay-as-you-go. Issue your key from each service's dashboard, and enter it in the "API Key" field rather than writing it into the code. You can also choose a model name using 🔄 Fetch List (OpenRouter lists hundreds of models). Whether you can call the API directly from the browser depends on each service's CORS support (OpenRouter and DeepInfra support it; some services will return Failed to fetch, in which case they can't be used from the browser).

💡 What Kinds of Models Can You Build? Idea Collection

Requesting a model on "a theme related to your own field" can also make a great class report.

🚗
Traffic Congestion
Cars move on a grid and stop at signals. Explore the conditions under which congestion arises.
🐟
Predator–Prey
A predator–prey model where herbivore and carnivore populations oscillate periodically.
🌿
Forest Fire
The higher the tree density, the more the fire spreads. Explore the critical density threshold.
🏙
Urban Population Movement
People move based on "livability." An extended version of the segregation model.
💬
Rumor Spread
Who talks to whom? Network structure changes the speed of spread.
🦟
Spatial Spread of Disease
An extension of SIR where individuals move around while infecting others.
🏭
Market Model
An economic ABM where prices are determined through interactions between buyers and sellers.
🧠
Opinion Formation
Opinions converge or polarize as they're pulled toward nearby people.
🐝
Bee Foraging
A waggle dance guides fellow bees to flower patches. Modeling information transfer.
Tips for tailoring it to your field It works well to first organize things into the form "agent = ○○, environment = △△, interaction = □□" before asking the generative AI. It doesn't need to be perfectly accurate; you can always modify it later.

🔧 When Things Don't Work

SymptomSolution
An error appears and it won't runThe line number and a hint about the cause are shown. Read them first. If it still doesn't work, paste the red error text as-is into the generative AI and ask it to fix it. ❔ Help also lists syntax that can't be used.
Nothing is displayedCheck whether you pressed ▶ Apply. The order is: press it, then press ▶ Run.
Too fast to seeLower the "Speed." Set it to very slow if you want to see one step at a time.
Heavy / stutteringReduce the number of agents, or raise "Draw Skip" to something like 1/4.
The generative AI's code doesn't workAsk again: "Please fix this according to the specification. Do not use document.*, import, or class."
On the free tier, code gets cut off partway / explanatory text gets mixed inPaste only the contents of the code block. If it's cut off, prompt it to "continue," or ask again. The prompt already includes instructions to "output only one block, in full, without omissions."
Note when pasting code Copy only the contents of the code block (```javascript ... ```), not the generative AI's entire reply. Using the "Copy" button in the top-right of the code block automatically copies only its contents.

📚 References and Sources

These are the primary sources on which the built-in models are based. All code is an original implementation by this project.

  • Elementary Cellular Automaton (ECA): Wolfram, S. (1983). Statistical mechanics of cellular automata. Reviews of Modern Physics, 55(3), 601–644. / Wolfram, S. (2002). A New Kind of Science. Wolfram Media.
  • Game of Life: Gardner, M. (1970). Mathematical Games: The fantastic combinations of John Conway's new solitaire game "life". Scientific American, 223(4), 120–123.
  • Segregation Model: Schelling, T. C. (1971). Dynamic models of segregation. Journal of Mathematical Sociology, 1(2), 143–186.
  • Flocking (Boids): Reynolds, C. W. (1987). Flocks, herds and schools: A distributed behavioral model. Computer Graphics (SIGGRAPH '87), 21(4), 25–34.
  • Ant Pheromones: Deneubourg, J.-L., Aron, S., Goss, S., & Pasteels, J. M. (1990). The self-organizing exploratory pattern of the Argentine ant. Journal of Insect Behavior, 3(2), 159–168.
  • Spatial Prisoner's Dilemma: Nowak, M. A., & May, R. M. (1992). Evolutionary games and spatial chaos. Nature, 359, 826–829.
  • SIR Epidemic Model: Kermack, W. O., & McKendrick, A. G. (1927). A contribution to the mathematical theory of epidemics. Proceedings of the Royal Society A, 115(772), 700–721.
  • Social Particle Swarm (SPS): An original model by this project's author group. Nishimoto, K., Suzuki, R., & Arita, T. (2023). Social Particle Swarm model for investigating the complex dynamics of social relationships. Psychologia, 65(2), 185–210. https://doi.org/10.2117/psysoc.2023-B039
