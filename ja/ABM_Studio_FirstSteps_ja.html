🤔 ABM Studio って何？

ABM Studio は，ブラウザで動く「モデル（実験）」のツールです．インストール不要．ファイルをダブルクリックするだけで使えます．パソコンだけでなくスマートフォン・タブレットでも画面が自動で調整されて使えます．

エージェントベースモデル（ABM）とは，「たくさんの個体（エージェント）が，それぞれ簡単なルールに従って動く」モデル（実験）のことです．群れ・感染拡大・社会的な分離……どれも個体のルールだけから，驚くほど複雑な現象が生まれます．

ふつうはプログラミングが必要ですが，ABM Studio では 生成AI にコードを作ってもらって貼り付けるだけで，自分の興味あるモデルを動かせます．

このツールのねらい（考え方） 近年の生成AIの進展は，複雑系や人工生命の「作って理解する（構成論的）」モデリングを大きく変えつつあります．プロンプトで骨子を与えれば，完全な仕様でなくても様々なモデルを自動生成でき，必要に応じて AI に説明してもらって理解したり，対話しながらアイデアを洗練したりできます．ただし，全部を AI に任せると出来上がるものがバラバラになりがちです．
ALifeCoreStudio（ABM・EVO・IEC の3スタジオ）は，モデル構築・可視化・分析の共通の枠組みを固定したうえで，モデルの本質的な部分だけを生成AIで生み出せるようにした道具です．これにより，プログラミング未経験の初心者が発想を自由に形にする／学生が AI と協働してモデルを育てる／研究者が素早くプロトタイプを作る，といった使い方ができます．
枠組みの中で可能なモデルを自由に生み出すことを通じて，構成論的アプローチによる科学的理解を加速し，「どんな世界がありうるか」を思い描いて動かす楽しさを広げたい——それがこのツールのねらいです．
これだけあれば OK ABM Studio（HTML ファイル）を開いたブラウザ ＋ 生成AIサービス（ChatGPT・Gemini・Claude など，無料版で十分）
EVO Studio との違い ABM Studio は「個体のルールから現象が生まれる」のを観察する道具．EVO Studio は「良い答えを進化で探す」道具です．ABM では エージェント・環境・相互作用の3点を決めるのがいちばん大事なポイントになります．

▶️ まずビルトインモデルを動かしてみよう

ABM Studio には最初からモデルが入っています．まずそれを動かしてみましょう．

1
モデルを選ぶ

画面下のコードバーにあるドロップダウン（「── モデルを選択 ──」）からモデルを選びます．クリックすると自動でセットされます．

2
▶ 実行 を押す

キャンバスでモデル（実験）が動き始めます．もう一度押すと一時停止．右パネルのスライダーを動かすとパラメータがリアルタイムに変わります．

おすすめの見方 まず「群れ（フロッキング）」を動かして，分離・整列・凝集の3つの重み（0〜6）をひとつずつ動かしてみてください．整列を上げると画面左上の整列度 φ が 1 に近づき，凝集を上げると密集し，分離を上げると間隔が広がります．プログラムを読まなくても「どの規則が何に効くか」が分かります．
知っておくと得な機能
  • このモデルの概要：右パネル上部に，エージェント・環境・相互作用の説明が出ます．動かす前に読むと理解が早い．
  • 数値の直接入力：スライダー右の数値欄に，キーボードで正確な値を打ち込めます．
  • ゆっくり観察：速度スライダーはとても遅くもでき，1 ステップずつ追えます（ECA は 1 行ずつが見やすい）．
  • グラフで定量的に：状態数の推移グラフ（例：SIR の S/I/R 人数，ECA の ON セル数）で現象を確かめられます．
  • 結果をくらべる：📸 現在を保存 でグラフに重ねて A/B 比較．⬇ CSV保存 で Excel 用に出力．
  • 📦 一式DL：「実験の保存・比較」の 📦 一式DL で，初期化以降のデータを ZIP にまとめて保存できます．中身は実験設定（パラメータ・初期状態・停止条件・乱数シード 等）を書いた metadata.json，グラフごとの .csv，全データの data.json，そしてモデルのコードそのもの model.js です．あとから分析したり，同じ実験を再現したりするのに使えます．
    さらに 状態を記録（追っかけ再生・再生用） をオンにしてから実行すると，各ステップの状態が frames.jsonl に保存されます（観察するだけならオフのままでOK・高速）．書き出した ZIP をリポジトリ直下の ALifeCoreStudio_Viewer.html にドロップすると，記録した各ステップをそのモデル自身の絵で再生できます（組み込み・改変・新規どれでも動作）．
  • 走らせながら見返す：状態の記録が始まると，実行ボタンの下にタイムラインが出ます．LIVE は既定でオンで，フィールドは最新のステップを追います．バーを動かす（または LIVE のチェックを外す）と，裏で実験を続けたまま，過去の任意のステップへ戻れます（ライブ配信のシークバーと同じ感覚です）．▶ で記録した分を連続再生でき，各グラフには現在地を示す琥珀色のマーカーが出ます．LIVE に再びチェックすると最新に戻ります．どこまで遡れるかは間隔の隣の 上限（既定 500 MB，無制限まで）で決まります．
  • 重いとき：「描画間引き」を 1/4 などに上げると軽くなります．❔ ヘルプ や パラメータ横の ⓘ も活用．
  • 💾 HTML出力：コードバーのボタンで，いま動かしているモデルだけを実行できる単体HTMLファイルとして書き出せます．編集UIなしのシンプルな画面になるので，配布・提出・発表用の保存に．

👁️ 画面の見かた（概要・グラフ・速度）

動かす前後で，次の4か所を見ると理解がぐっと深まります．

1
このモデルの概要

右パネルのいちばん上に，エージェント（何が動くか）・環境・相互作用の説明が出ます．まずここを読みましょう．

2
パラメータ（スライダー＋数値入力）

スライダーで動かすほか，右の数値欄に正確な値を入力できます（例：ルール番号 110）．横の ⓘ に意味の説明が出ます．

3
速度（ゆっくり〜高速）

速度スライダーはとても遅くもできます．1 ステップずつ変化を追うのに便利です．

4
グラフ（状態数の推移）

多くのモデルに推移グラフが付きます．数の動きで現象を定量的に確かめ，📸 現在を保存 で条件をくらべられます．グラフ右上の ⚙ 軸 を押すと，縦軸・横軸の範囲を「自動調整」のままにするか，min/max を指定して手動設定するかを選べます．

✏️ 動いているモデルを改変しよう（まずはここから）

いちばん簡単な入り口がこれです．ビルトインのモデルを少し変えるだけで，自分の関心に近づけられます．「✏️ 改変プロンプト」ボタンを押すと，現在のコードと改変指示がセットでコピーされるので，ゼロから書くより確実です．

📖 説明プロンプト と モデル名 いま動かしているモデルの「仕組み」を知りたいときは 📖 説明プロンプト を押します．現在のコードを含む説明依頼がコピーされるので，生成AI に貼ると概要・アルゴリズムの説明・疑似コードで丁寧に解説してくれます．また生成・改変されたコードには const TITLE = 'モデル名' が付き，ブラウザのタブ名・「概要」の見出し・💾 .js保存 のファイル名（例 住み分けモデル.js）に反映されます．
1
「✏️ 改変プロンプト」を押す

コードバーにあります．現在のコードが自動的にプロンプトに含まれます．

2
生成AI に貼り付けて「変えたいこと」を書く

貼り付けたプロンプトの末尾にある【改変したい内容】に，変えたい内容を日本語で1〜2 項目ずつ箇条書きします．

3
返ってきたコードを全部入れ替える

コード欄で全選択（Ctrl+A）して貼り付け（Ctrl+V），「▶ 適用」を押します．

モデル別・改変リクエストの例（各2つ）💬

ベースモデル生成AI への改変指示のアイデア
📏 ECA
  • ルール番号の代わりに，近傍8パターン（111〜000）の出力を8本の ON/OFF スイッチで指定できるようにして．
  • 状態を 0/1/2 の3値に拡張し，それぞれ別の色で表示して．
🔲 ライフゲーム
  • 「誕生」「生存」の近傍数の条件をスライダーで変えられるようにして（B36/S23 など）．
  • セルの「年齢」（生き続けた世代数）に応じて色をだんだん濃くして，長く生き残っている安定構造が一目で分かるようにして．
🏘 住み分け
  • 住民を3種類に増やして，それぞれ別の色で表示して．
  • 満足のしきい値（許容度）を種類ごとに別スライダーにして，分離の進み方を比べられるようにして．
🐦 群れ
  • 捕食者を1匹追加して，個体が一定距離に入ったら逃げるようにし，捕食者の速度をスライダーにして．
  • 画面に円形の障害物を置いて避けて通るようにし，半径をスライダーにして．
🐜 アリ
  • 巣を2つに増やして，2つのコロニーがどちらだけ多く餌を集められるか競争する様子を見られるようにして．
  • フェロモンを「巣へ戻る用」と「餌を探す用」の2種類に分け，別の色で表示して．
🤝 囚人のジレンマ
  • まわりをまねる範囲を「4近傍／8近傍」で切り替えられるようにして，協力の塊の形がどう変わるか比べられるようにして．
  • 直前の世代から戦略が変わったセルだけを光らせて，協力と裏切りが「せめぎ合う境界」が見えるようにして．
🦠 SIR
  • 初期にワクチン接種済み（免疫あり）の個体を加え，接種率スライダー（0〜1）を追加して．
  • 回復者が時間とともに免疫を失い再び感染しうる SIRS モデルにして，免疫喪失率をスライダーにして．
⚪ SPS
  • 粒子の動いた跡を短い尾として残して，集まる（クラスター化）／散らばるの流れが目で追えるようにして．
  • 今いくつの「塊（クラスター）」に分かれているかを数えて画面に表示し，集合（数が減る）と崩壊（数が増える）のくり返しを数で追えるようにして．
改変のコツ 一度に大きく変えようとすると失敗しやすいです．小さな変更を 1〜2 個ずつ頼んで，動くたびに確認していくのがおすすめです．

✨ 生成AI に新しいモデルを作ってもらおう

改変に慣れたら，ゼロから新しいモデルも作れます．「✨ 新規作成プロンプト」ボタンを押すと，生成AI に渡すための仕様書がクリップボードにコピーされます．

1
「✨ 新規作成プロンプト」を押す

画面下部のコードバーにあります．「コピーしました」と出れば OK．

2
生成AI に貼り付けて書き換える

生成AI のチャット欄に貼り付け，【実装するモデル】の欄を作りたいモデルに書き換えて送信します．

3
コードをコピーして ABM Studio に貼る

生成AI が出力したコードブロック（```javascript ... ```）の中身だけをコピーして，コード欄に貼り付け「▶ 適用」を押します．

こんなふうに頼むと伝わりやすい 💬

ABM では「誰が（エージェント）・どんな環境で・どう相互作用するか」を伝えるのがコツです．

🙋
学生の入力例
感染症が広がって，回復した人が免疫を持つモデルを作って．
感染確率と回復確率をスライダーで変えられるようにして，感染者数の時系列グラフも出して．
🙋
学生の入力例
格子の上を車エージェントが動いて，信号待ちで止まる交通モデルを作って．

📋 生成AI へのリクエスト例（【実装するモデル】欄に書く内容）
テーマ（例：感染症・交通・生態系） のモデルを作ってください．

エージェントは どんな個体（例：人・車・鳥），
環境は どんな場（例：格子・トーラス平面・障害物あり），
相互作用は 何をする（例：近くを避ける・接触で感染・フェロモンに従う）．

スライダーで変えたいパラメータ：例：個体数・感染確率・速度
グラフで見たいもの：例：感染者数の時系列・協力率（なければ省略 OK）

🐍 コードを Python に変換しよう（requirements.txt 付き）

ABM Studio の JavaScript モデルを，そのままレポートや研究に使える Python スクリプトに変換したいときは「🐍 Python化プロンプト」ボタンを使います．コードバーにあります．

1
「🐍 Python化プロンプト」を押す

現在コード欄にあるモデルの内容が自動的にプロンプトへ含まれます．

2
生成AI に貼り付けて送信する

そのまま貼り付けるだけで OK です．書き換える箇所はありません．

3
2つのコードブロックを保存する

生成AI からは Python スクリプトと requirements.txt の2つのコードブロックが返ってきます．それぞれ model.py・requirements.txt として保存し，同じフォルダに置きます．

4
手元の環境で実行する

ターミナルで pip install -r requirements.txt のあと python model.py を実行すると，matplotlib のウィンドウで同じモデルが動きます．

こんなときに便利 ブラウザ上での観察はここまでにして，数値計算や統計処理，論文・レポート用の図の作成を Python（numpy・matplotlib・pandas など）でじっくり行いたいときに役立ちます．ABM Studio 側で「概要」欄に書いた説明やパラメータの意味（help）も，変換時にコメントとして引き継がれます．

🤖 生成AI の API に直接つないで生成する（ローカル / クラウド）

生成AI にコピー＆ペーストする代わりに，自分のPCで動く LLM（LM Studio など）に直接つないで，改変や新規作成を Studio の中だけで完結させることもできます．コードを貼ったり戻したりする手間がなく，ネットに送らず手元で動かせるのが利点です．OpenAI 互換 API なら何でも使えます（LM Studio・Ollama・OpenAI など）．

必要なもの LM Studio（無料）などの OpenAI 互換サーバ．モデルを1つロードし，ローカルサーバを起動しておきます．
1
LM Studio でサーバを起動する

モデルをロード →「Local Server」を Start．Server Settings で「Enable CORS」を ON にしておきます（ブラウザから接続するために必須）．

2
「🤖 AI生成」を押す

画面下部のコードバーにあります．設定パネルが開くので，エンドポイント（既定 http://localhost:1234）とモデル名を確認します．モデル名は 🔄 一覧取得 で選べます．設定は記憶されるので次回からは不要です．

3
「改変／新規作成」を選び，指示を書いて ▶ 送信

「✏️ 既存コードを改変」か「✨ 新規作成」を選び，やりたいことを書いて送信します．生成されたコードは自動でコード欄に入ります．内容を確認して ▶ 適用 で実行します．

うまく繋がらないとき 「Failed to fetch」はサーバ未起動・CORS 未設定・URL 違いが主な原因です．まずブラウザで http://localhost:1234/v1/models を直接開いて JSON が出るか確認してください．出れば LM Studio 側は正常です．モデル名は手入力でも送信できます．

クラウドの生成AIサービスを使う（OpenRouter・DeepInfra・OpenAI など）

ローカルだけでなく，OpenAI 互換のクラウド API も同じパネルから使えます．自分でサーバを立てる必要はなく，「エンドポイント」に各サービスのベースURL，「API キー」に発行したキー，モデル名を入れるだけです．

サービスエンドポイント（Base URL）モデル名の例
OpenRouterhttps://openrouter.ai/api/v1openai/gpt-4o-mini，deepseek/deepseek-chat など
DeepInfrahttps://api.deepinfra.com/v1/openaimeta-llama/Meta-Llama-3.1-8B-Instruct など
OpenAIhttps://api.openai.com/v1gpt-4o-mini など
クラウド利用の注意 これらは API キーが必須で，多くは従量課金です．キーは各サービスのダッシュボードで発行し，コードに書かず「API キー」欄に入れてください．モデル名は 🔄 一覧取得 でも選べます（OpenRouter は数百種類出ます）．ブラウザから直接呼べるかは各サービスの CORS 対応によります（OpenRouter・DeepInfra は対応。サービスによっては Failed to fetch になり，その場合はブラウザからは使えません）．

🔧 うまくいかないときは

症状対処法
エラーが出て動かない原因の行番号とヒントが日本語で出ます．まず読む．直らなければ赤いエラー文をそのまま 生成AI に貼って「直して」と頼む．❔ ヘルプ に使えない書き方の一覧もあります．
何も表示されない▶ 適用 を押したか確認．押してから ▶ 実行 の順番です．
速すぎて見えない「速度」を下げる．1 ステップずつ見たいときはとても遅くに設定．
重い・カクつく個体数を減らす，「描画間引き」を 1/4 などに上げる．
生成AI のコードが動かない「仕様書に従って修正してください．document.*・import・class は使わないでください」と再依頼．
無料版でコードが途中で切れる／説明文が混ざるコードブロックの中身だけを貼る．途中で切れたら「続きを出して」と促す，または再依頼．プロンプトには「1ブロックだけ・省略せず全文出力」の指示が入っています．
コードを貼るときの注意 生成AI の返答全体ではなく，コードブロック（```javascript ... ```）の中身だけをコピーしてください．コードブロック右上の「コピー」ボタンを使うと自動的に中身だけになります．
