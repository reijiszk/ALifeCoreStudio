🤔 EVO Studio って何？

EVO Studio は，ブラウザで動く「進化（進化計算）」の実験ツールです．インストール不要．ファイルをダブルクリックするだけで使えます．

遺伝的アルゴリズム（GA）というのは，生物の進化をまねた問題の解き方です．「個体（候補となる答え）の集団」を用意し，評価 → 選択 → 交叉（組み換え）→ 突然変異 → 次世代をくり返すと，世代を重ねるごとに「良い答え」が自然に磨かれていきます．

EVO Studio では，GA のしくみ（選択・交叉・突然変異・エリート保存）はエンジンが全部やってくれます．あなたが決めるのは「遺伝子の形」「良し悪しの測り方（評価関数）」「絵の描き方」の3つだけ．しかもそれは 生成AI に作ってもらって貼り付けるだけでかまいません．

このツールのねらい（考え方） 近年の生成AIの進展は，複雑系や人工生命の「作って理解する（構成論的）」モデリングを大きく変えつつあります．プロンプトで骨子を与えれば，完全な仕様でなくても様々なモデルを自動生成でき，必要に応じて AI に説明してもらって理解したり，対話しながらアイデアを洗練したりできます．ただし，全部を AI に任せると出来上がるものがバラバラになりがちです．
ALifeCoreStudio（ABM・EVO・IEC の3スタジオ）は，モデル構築・可視化・分析の共通の枠組みを固定したうえで，モデルの本質的な部分だけを生成AIで生み出せるようにした道具です．これにより，プログラミング未経験の初心者が発想を自由に形にする／学生が AI と協働してモデルを育てる／研究者が素早くプロトタイプを作る，といった使い方ができます．
枠組みの中で可能なモデルを自由に生み出すことを通じて，構成論的アプローチによる科学的理解を加速し，「どんな世界がありうるか」を思い描いて動かす楽しさを広げたい——それがこのツールのねらいです．
これだけあれば OK EVO Studio（HTML ファイル）を開いたブラウザ ＋ 生成AIサービス（ChatGPT・Gemini・Claude など，無料版で十分）
ABM Studio との違い ABM Studio は「個体のルールから現象が生まれる」のを観察する道具．EVO Studio は「良い答えを進化で探す」道具です．Evo では 評価関数（fitness）＝大きいほど良い値を決めるのがいちばん大事なポイントになります．

▶️ まずビルトインモデルを動かしてみよう

EVO Studio には最初からモデルが入っています．まずそれを動かしてみましょう．

1
モデルを選ぶ

画面下のコードバーにあるドロップダウン（「── モデルを選択 ──」）からモデルを選びます．

2
▶ 進化開始 を押す

世代が進み，グラフの適応度（最良・平均）が上がっていきます．もう一度押すと一時停止．⏭ 1世代 で 1 世代ずつ進めることもできます．⟳ 初期化 でランダムな初期集団からやり直せます．「最大世代」に達すると自動的に止まります（既定は ⏹ 停止のみ。右のセレクタを 🔁 ループ に切り替えると、その世代で初期化して繰り返します）．

おすすめの見方 まず「⑤ 巡回セールスマン問題（TSP）」を選び，▶ 進化開始．最初はぐちゃぐちゃだった巡回路が，世代を追うごとに短くスッキリした経路に整っていきます．実行速度（世代/秒）を下げると，改善のようすがよく見えます．
知っておくと得な機能
  • 実行速度：左の「実行速度」スライダーは 世代/秒．下げるとゆっくり，上げると一気に進みます．
  • 結果をくらべる：少し進化させて 📸 現在を保存 を押すと，グラフに重ねて残せます．
  • データを保存：グラフの 💾 / ⬇ CSV保存 で結果を Excel 用 CSV に保存．
  • 📦 一式DL：「実験の保存・比較」の 📦 一式DL で，初期化以降のデータを ZIP にまとめて保存できます．中身は実験設定（パラメータ・停止条件・乱数シード 等）を書いた metadata.json，世代ごとの適応度の .csv，全データの data.json，そしてモデルのコードそのもの model.js です．あとから分析・再現するのに使えます．
    さらに 状態を記録（追っかけ再生・再生用） をオンにしてから実行すると，各世代の状態が frames.jsonl に保存されます（観察するだけならオフのままでOK・高速）．書き出した ZIP をリポジトリ直下の ALifeCoreStudio_Viewer.html にドロップすると，記録した各世代をそのモデル自身の絵で再生できます（組み込み・改変・新規どれでも動作）．
  • 走らせながら見返す：状態の記録が始まると，実行ボタンの下にタイムラインが出ます．LIVE は既定でオンで，表示は最新の世代を追います．バーを動かす（または LIVE のチェックを外す）と，裏で進化を続けたまま，過去の任意の世代へ戻れます（ライブ配信のシークバーと同じ感覚です）．▶ で記録した分を連続再生でき，各グラフには現在地を示す琥珀色のマーカーが出ます．LIVE に再びチェックすると最新に戻ります．どこまで遡れるかは間隔の隣の 上限（既定 500 MB，無制限まで）で決まります．
  • 重いとき：「個体数」を下げる，生物モデルなら「評価ステップ数」を下げると軽くなります．
  • 💾 HTML出力：コードバーのボタンで，いま動かしているモデルだけを実行できる単体HTMLファイルとして書き出せます．編集UIなしのシンプルな画面になるので，配布・提出・発表用の保存に．

👁️ 最良だけ／集団全体を見る

画面に大きく表示されるのは，その世代の最良個体（いちばん成績が良かった1体）です．たくさんの個体が裏で競争していて，その勝者を見せている，というイメージです．

でも「集団全体のばらつき」を見るのも，進化を理解するうえで大切です．再生コントロールの下にある 表示 トグルで切り替えられます．

1
最良のみ（既定）

最良個体だけを大きく表示．生物モデルなら歩く様子がアニメーションで見えます．

2
全個体

集団の上位の個体を適応度順にタイル表示します（左上の ★ が最良）．隣に出る 表示数 スライダーで，何個体を並べるか（4〜36）を選べます．世代が進むと各タイルの中身も更新されます．

使い分けのコツ 普段は「最良のみ」で進め，ときどき「全個体」に切り替えて多様性（いろいろな形・経路が共存しているか）を確認すると，進化が「収束しすぎ」か「まだ探索中」かが分かります．タイルが小さいと感じたら表示数を 9 などに減らすと大きく見えます．

✏️ 動いているモデルを改変しよう

ビルトインや自作のモデルを「もう少し変えたい」と思ったら，「✏️ 改変プロンプト」ボタンを使います．現在のコードと改変指示がセットでコピーされます．

📖 説明プロンプト と モデル名 いま動かしているモデルの「仕組み」を知りたいときは 📖 説明プロンプト を押します．現在のコードを含む説明依頼がコピーされるので，生成AI に貼ると概要・アルゴリズムの説明・疑似コードで丁寧に解説してくれます．また生成・改変されたコードには const TITLE = 'モデル名' が付き，ブラウザのタブ名・「説明」の見出し・💾 .js保存 のファイル名（例 質点バネ生物.js）に反映されます．
1
「✏️ 改変プロンプト」を押す

コードバーにあります．現在のコードが自動的にプロンプトに含まれます．

2
生成AI に貼り付けて「変えたいこと」を書く

貼り付けたプロンプトの末尾にある【改変したい内容】に，変えたい内容を日本語で箇条書きするだけです．

3
返ってきたコードを全部入れ替える

コード欄で全選択（Ctrl+A）して貼り付け（Ctrl+V）し，「▶ 適用」を押します．

改変リクエストの例 💬

【改変したい内容】の箇条書きに，以下のようなアイデアを書いてみましょう．

ベースモデル 生成AIへの改変指示のアイデア
① 関数最適化
  • 評価関数を Rastrigin から Sphere 関数に変えて，最低値が 0 になるようにして．
  • 変数の数を 2 次元から 3 次元（x，y，z）に増やして．
② 質点バネ生物
  • fitness を「右への距離」から「ジャンプの最高到達点」に変えて．
  • 重力スライダーを追加して．
③ ソフトボディ生物
  • fitness を「移動速度」から「体の重心の高さ」に変えて．
  • 地面に障害物を置いて，それを乗り越えるようにして．
④ ナップザック
  • 品物を 50 個に増やして，重さと価値をもっとばらつかせて．
  • 容量を変えるスライダーの範囲を広げて．
⑤ 巡回セールスマン
  • 都市の数を 40 に増やして．
  • 都市を円周上に並べて（最短路が円になるはず）．
改変のコツ 一度に大きく変えようとすると失敗しやすいです．小さな変更を 1〜2 個ずつ頼んで，動くたびに確認していくのがおすすめです．

✨ 生成AI に新しいモデルを作ってもらおう

EVO Studio には「✨ 新規作成プロンプト」ボタンがあります．これを押すと，生成AI に渡すための仕様書がクリップボードにコピーされます．

1
「✨ 新規作成プロンプト」を押す

画面下部のコードバーにあります．「コピーしました」と出れば OK．

2
生成AI に貼り付けて書き換える

生成AI のチャット欄に貼り付け，【実装する題材】という欄を解きたい問題に書き換えて送信します．

3
コードをコピーして EVO Studio に貼る

生成AI が出力したコードブロック（```javascript ... ```）の中身だけをコピーして，EVO Studio のコード欄に貼り付け「▶ 適用」を押します．

こんなふうに頼むと伝わりやすい 💬

GA では「何を遺伝子にして，何を最大化（最小化）したいか」を伝えるのがコツです．

🙋
学生の入力例
実数の遺伝子で f(x,y)=sin(x)+cos(y)−0.1(x²+y²) を最大化するモデルを作って．
探索のようすを x–y 平面に点で描いてほしい．
🙋
学生の入力例
棒人間のような生き物を，関節の角度の周期運動でできるだけ右へ歩くように進化させたい．
最良個体が歩くアニメーションも見たいです．
📋 生成AI へのリクエスト例（【実装する題材】欄に書く内容）
解きたい問題（例：最短経路・関数最適化・歩く生物） を進化で解くモデルを作ってください．

遺伝子（候補の答え）は 何か（例：各都市の順番・実数のパラメータ・形と動き）．
評価関数（大きいほど良い）は 何を最大化したいか（例：−経路長・関数値・進んだ距離）．

スライダーで変えたいパラメータ：例：個体数・突然変異率・都市数（なければ省略 OK）
最良個体を動かして見せたい場合はその旨も書いてください．

🤖 生成AI の API に直接つないで生成する（ローカル / クラウド）

生成AI にコピー＆ペーストする代わりに，自分のPCで動く LLM（LM Studio など）に直接つないで，改変や新規作成を Studio の中だけで完結させることもできます．コードを貼ったり戻したりする手間がなく，ネットに送らず手元で動かせるのが利点です．OpenAI 互換 API なら何でも使えます（LM Studio・Ollama・OpenAI など）．

必要なもの LM Studio（無料）などの OpenAI 互換サーバ．モデルを1つロードし，ローカルサーバを起動しておきます．
1
LM Studio でサーバを起動する

モデルをロード →「Local Server」を Start．Server Settings で「Enable CORS」を ON にしておきます（ブラウザから接続するために必須）．

2
「🤖 AI生成」を押す

画面下部のコードバーにあります．設定パネルが開くので，エンドポイント（既定 http://localhost:1234）とモデル名を確認します．モデル名は 🔄 一覧取得 で選べます．設定は記憶されるので次回からは不要です．

3
「改変／新規作成」を選び，指示を書いて ▶ 送信

「✏️ 既存コードを改変」か「✨ 新規作成」を選び，やりたいことを書いて送信します．生成されたコードは自動でコード欄に入ります．内容を確認して ▶ 適用 で実行します．

うまく繋がらないとき 「Failed to fetch」はサーバ未起動・CORS 未設定・URL 違いが主な原因です．まずブラウザで http://localhost:1234/v1/models を直接開いて JSON が出るか確認してください．出れば LM Studio 側は正常です．モデル名は手入力でも送信できます．

クラウドの生成AIサービスを使う（OpenRouter・DeepInfra・OpenAI など）

ローカルだけでなく，OpenAI 互換のクラウド API も同じパネルから使えます．自分でサーバを立てる必要はなく，「エンドポイント」に各サービスのベースURL，「API キー」に発行したキー，モデル名を入れるだけです．

サービスエンドポイント（Base URL）モデル名の例
OpenRouterhttps://openrouter.ai/api/v1openai/gpt-4o-mini，deepseek/deepseek-chat など
DeepInfrahttps://api.deepinfra.com/v1/openaimeta-llama/Meta-Llama-3.1-8B-Instruct など
OpenAIhttps://api.openai.com/v1gpt-4o-mini など
クラウド利用の注意 これらは API キーが必須で，多くは従量課金です．キーは各サービスのダッシュボードで発行し，コードに書かず「API キー」欄に入れてください．モデル名は 🔄 一覧取得 でも選べます（OpenRouter は数百種類出ます）．ブラウザから直接呼べるかは各サービスの CORS 対応によります（OpenRouter・DeepInfra は対応。サービスによっては Failed to fetch になり，その場合はブラウザからは使えません）．

🔧 うまくいかないときは

症状対処法
エラーが出て動かない 原因の行番号とヒントが日本語で表示されます．まず読む．直らなければ赤いエラー文をそのまま 生成AI に貼って「直して」と頼む．右上の ❔ ヘルプ に使えない書き方の一覧もあります．
何も表示されない ▶ 適用 を押したか確認．押してから ▶ 進化開始 の順番です．
適応度（グラフ）が伸びない 「突然変異率」を少し上げて探索を広げる，「選択圧（トーナメント）」を上げて良い個体を残しやすくする，「個体数」を増やす，をそれぞれ試す．問題が難しすぎる場合は規模を小さく．
すぐ収束して同じ答えばかり 「突然変異率」を上げる／「エリート保存」を下げる／「個体数」を増やすと多様性が保てます．全個体 表示でばらつきを確認．
速すぎて見えない 「実行速度（世代/秒）」を下げる．1 世代ずつ見たいときは ⏭ 1世代．
重い・カクつく 「個体数」を下げる．生物モデルは「評価ステップ数」を下げる．全個体 表示中なら「表示数」を減らす．
生成AI のコードが動かない 「仕様書に従って修正してください．document.*・import・class は使わないでください」と再依頼．
無料版でコードが途中で切れる／説明文が混ざる コードブロックの中身だけを貼る．途中で切れたら「続きを出して」と促す，または再依頼．プロンプトには「1ブロックだけ・省略せず全文出力」の指示が入っています．
コードを貼るときの注意 生成AI の返答全体ではなく，コードブロック（```javascript ... ```）の中身だけをコピーしてください．コードブロック右上の「コピー」ボタンを使うと自動的に中身だけになります．

📚 参考文献・出典

ビルトインモデルが題材にしている代表的な原典です。コードはすべて本プロジェクトによる独自実装です（ソフトボディ生物は下記のとおり既存研究の着想を参考に、コードは独自に実装しています）。

  • 遺伝的アルゴリズム（GA）：Holland, J. H. (1975). Adaptation in Natural and Artificial Systems. University of Michigan Press.／Goldberg, D. E. (1989). Genetic Algorithms in Search, Optimization, and Machine Learning. Addison-Wesley.
  • 質点バネ生物（仮想生物の進化）：Sims, K. (1994). Evolving virtual creatures. SIGGRAPH '94, 15–22. — 仮想生物を進化させる研究の原点です。Sims が扱ったのは関節でつながれた立体ブロックからなる3次元の生物とその神経制御器であり、本ツールのモデルはその再実装ではなく、同じ流れに着想を得てはるかに単純な2次元の質点バネ系として独自に実装したものです。
  • ソフトボディ生物（ボクセル）：Bhatia, J., Jackson, H., Tian, Y., Xu, J., & Matusik, W. (2021). Evolution Gym: A large-scale benchmark for evolving soft robots. NeurIPS 2021. — 「ボクセルでソフトロボットを進化させる」という着想を Evolution Gym（github.com/EvolutionGym/evogym, MIT License）から得たものです。物理モデル（位置ベース動力学）を含むコードはすべて独自に実装しており、EvoGym のソースコードは使用していません。
  • ナップザック問題・巡回セールスマン問題（TSP）：いずれも組合せ最適化の古典的問題です（標準的な教科書を参照）。

🙏 謝辞

本ツールは NetLogo（Wilensky, U., 1999, Center for Connected Learning and Computer-Based Modeling, Northwestern University）から大きな影響を受けています。著者はこれまで NetLogo を自身の理解や授業に活用しており、その経験が本ツールの着想と設計の土台になっています。ここに記して深く感謝します。
