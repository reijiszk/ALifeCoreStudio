v1.0EVO Studio User Manual

A genetic algorithm (GA) experiment environment that runs in your browser

1What is EVO Studio?

EVO Studio is a genetic algorithm (GA) experiment environment that runs entirely in your browser. No installation, no account registration: just double-click the file to launch it.

A GA is an optimization method that repeats "evaluate → select → crossover → mutate → next generation across a population of individuals to evolve better solutions." In EVO Studio, the engine handles this GA loop (selection, crossover, mutation, elitism). Users write only the following three things in JavaScript (a generative AI can write them for you, too).

The idea behind this tool Recent advances in generative AI are reshaping the "understanding by building" (constructive) style of modeling in complex systems and artificial life. By giving a prompt with just the skeleton of an idea, not a complete specification, you can auto-generate a wide variety of models, have the AI explain them when you want to understand them, and refine ideas through dialogue. Letting the AI generate everything, however, tends to produce wildly inconsistent results.
ALifeCoreStudio (the three studios, ABM / EVO / IEC) keeps a common framework for model construction, visualization, and analysis fixed and lets generative AI produce only the essential parts of a model. It is intended for beginners with no programming experience giving free form to their ideas, students growing models together with AI, and researchers building prototypes quickly. By making it easy to generate possible models freely within a shared framework, it aims to accelerate the constructive approach to scientific understanding and to spread the joy of imagining and running "what worlds could be."
The 3 Things You Decide ① GENE (the gene format), ② fitness(genome, params) (the evaluation function, where higher is better), and ③ draw(ctx, state, W, H, params) (rendering). For a quantity you want to minimize, flip the sign and return it (return -f).

What it can do: render the population's evolution in real time / record a chart of fitness (best/average) / tile-display the whole population (top individuals), not just the best / change parameters with sliders / save run results and overlay them on the chart for comparison / save field images and record video / export CSV / save and reload a model as .js, and more.

What it can't do: internet access, loading large databases, 3D rendering, and similar are not supported.

3Using Built-in Models

Choosing one from the code bar's dropdown ("── Select a model ──") automatically sets and applies the code. Press ▶ Start Evolution to begin evolving.

① Function Optimization (Bit-String GA)
Decodes a 32-bit gene into real numbers x, y and optimizes a function. The basic form of a GA.
② Mass-Spring Creature (2D Virtual Creature)
A spring system of 4 point masses + 6 muscles. Evolves to travel as far right as possible (animated).
③ Soft-Body Creature (Voxels)
Evolves a 5×5 voxel morphology and actuator phase. Maximizes walking distance.
④ Knapsack Problem
Inclusion/exclusion bit string. Maximizes total value within capacity (exceeding it is penalized).
⑤ Traveling Salesman Problem
Represents a permutation via the random-key method. Evolves the shortest route visiting all cities.
When You Want to Read the Code After applying a model, open ▸ Code to see all of that model's code. Read or modify it freely. Use 📋 Copy Spec to hand a generative AI the spec sheet plus the current code together.

4Evolution & Observation Controls

Run Controls

▶ Start Evolution runs continuously / pauses. ⏭ 1 Gen advances just one generation (handy for watching the mechanism closely). ⟳ Reset rebuilds from a random initial population.

Run Speed (Generations/sec)

The "Run speed" slider is generations advanced per second. Lower it to watch the improvement closely, raise it to speed through (fractional amounts accumulate internally too).

Draw Skipping and FPS

Raising "Draw skipping" speeds things up by skipping only the rendering, leaving computation untouched. Check the effect via the fps indicator in the header.

Max Generation and Behavior on Reaching It

The selector next to "Max generation" lets you choose the behavior when it's reached. The default is ⏹ Stop only, which stops at that generation without resetting (it does not go back to the start). Switch to 🔁 Loop to automatically reset and start over at that generation, letting you repeatedly observe typical behavior.

Stop Condition (STOP_COND)

If a model defines STOP_COND, it stops automatically once the condition (e.g., best fitness reaching a threshold) is met. Toggle the Stop Condition switch in the display to enable/disable it.

5Best-Only / All-Individuals View

What's shown large on the canvas is the generation's best individual (the single one with the highest fitness). Many individuals compete behind the scenes, and you're shown the winner (for creature models, viewReset/viewStep animate that individual every frame).

Switch this with the View toggle below the playback controls (default is Best Only).

ModeDetails
Best Only (default)Shows only the best individual, enlarged. Animated models move.
All IndividualsShows the population's top individuals as tiles, ordered by fitness (top-left ★ is the best; each tile shows rank and fitness). The adjacent Count slider (4–36) picks how many to show. For animated models, each tile moves independently.
Watching Diversity Occasionally switching to "All Individuals" reveals whether the population has converged to a single form or is still diverse. If the tiles feel too small, lowering Count to something like 9 makes them display bigger.

6Changing Parameters

You can tune the GA's behavior with sliders in the right panel's "Parameters." The engine automatically recognizes the following ids (each item's ⓘ shows a description).

ParameterMeaning
Population size popSizeIndividuals per generation. More gives a more stable search but is heavier (re-initializes on change).
Mutation rate mutationRateProbability each gene mutates. Too high makes the search random; too low makes it prone to local optima.
Crossover rate crossoverRateProbability of recombining two individuals.
Elitism elitismNumber of top individuals carried over unconditionally to the next generation. Keeps the best from regressing.
Selection pressure tournamentKNumber of participants in the tournament used to pick a parent. Larger favors stronger individuals.

Beyond these, model-specific parameters (e.g., evaluation steps, gravity, capacity) appear in the same panel. The live/reset toggle controls whether a change takes effect immediately or requires re-initialization (structural ones like population size always re-initialize).

7Saving & Comparing Results

Save & Compare Experiments

After evolving for a bit, press 📸 Save Current to keep that run overlaid on the fitness chart. Change parameters and run again to see the difference from before (A/B comparison).

Chart Saving / CSV

Use the chart's 💾 / ⬇ Save CSV to export per-generation fitness, etc. as CSV (includes a BOM, so it won't garble in Excel either).

📦 Download all data (ZIP, v1.0)

Pressing 📦 Download ZIP in the "Save/Compare Experiments" section exports all experiment data since initialization into a single ZIP, for later analysis or reproducing the same experiment. It contains:

FileContents

data.jsonStructured JSON bundling the settings, current run, and saved experiments. For loading from a program.
frames.jsonl
(only when "Record states" is on)		The state at each generation (one JSON frame per line, {"tick":<gen>, "state":…}). The data the bundled viewer replays generation by generation.

Live and time-shift playback

Record states in "Save and compare experiments" is on by default on a computer, so a timeline sits under the run buttons from the start and anything you notice while the run is going can be revisited. On phones and tablets it starts off, because recording is the most memory-hungry part of a run and those devices have the least to spare; tick the box there whenever you do want the timeline. The run seed is drawn afresh on every initialization and cannot be typed back in, so a run that was not recorded cannot be recovered. Recording stops on its own at the limit set beside the box. LIVE is checked by default and the display follows the newest generation. Drag the bar, or uncheck LIVE, and you can go back to any recorded generation while the run continues in the background, the same idea as the seek bar on a live video.

  • ▶ plays the recorded generations back at 12 frames per second, and stops when it catches up with the run.
  • The position readout shows where you are within what has been recorded, as in "generation 45 / 120". The number on the right keeps growing as the run continues.
  • An amber marker on each chart shows where the frame you are viewing sits in the time series.
  • Re-checking LIVE returns the display to the newest generation.

The granularity you can seek to is the recording interval (with "every 5 generations", you land on multiples of five). How far back you can go is set by the limit next to the interval: 500 MB by default, and no limit is available (recording then continues until the browser runs out of memory). The readout reports how much has been recorded, so the limit can be raised before it is reached.

Reproducing each generation, and viewer replay

So you can reproduce the state at each generation later, the ZIP carries two mechanisms:

  • Method A (deterministic seed): during a run the engine seeds the randomness and records the seed in settings.seed. The exact run can be reproduced from model.js + settings + seed (this works for AI-modified or newly-created models too).
  • Method B (recorded state): turn on Record states (for replay) in "Save/Compare Experiments" before running, and each generation's state is saved to frames.jsonl (you can also choose the interval). Leave it off when you are only observing; the run is faster that way.

Drop the exported ZIP onto the bundled ALifeCoreStudio_Viewer.html to replay each recorded generation along a timeline (play/pause, scrub, speed), rendered by the model's own drawing code. It works for built-in models as well as modified or newly-created ones.

Images & Video

Besides copying/saving canvas images, the recording feature lets you choose MP4 or WebM (falls back automatically depending on the environment). Useful for building presentation materials.

Saving & Loading Model Files

Use the code bar's 💾 Save .js to save the current model as .js, and 📂 Open to load it. Be sure to save any model you build yourself.

💾 HTML Export

Pressing the code bar's 💾 HTML Export exports a standalone HTML file that runs only the model currently running. It contains no code-editing area or generative-AI UI, leaving a simple screen with just the model's display, controls, and charts. Handy for distribution or as a submission for class or presentations.

8How the GA Engine Works

What the engine does every generation is as follows.

StageDetails
EvaluateCalls fitness(genome, params) on every individual to compute fitness (higher is better).
SelectTournament selection. Randomly picks tournamentK individuals and makes the best of them a parent.
CrossoverOne-point for the bit type, uniform for the real type (performed with probability crossoverRate).
MutationBit flip for the bit type, adds Gaussian noise for the real type (probability mutationRate, per gene).
ElitismThe top elitism individuals are copied to the next generation unconditionally.
A Trick for Handling Permutations (TSP) Holding a "permutation," like a tour, directly as the gene breaks under uniform crossover or Gaussian mutation. EVO Studio's TSP uses the random-key method. Each city holds a real-valued "key" (0–1), interpreted as visiting in ascending key order = the permutation. This lets the standard real-valued GA operations work as-is, always yielding a valid tour.

Tips for Describing What You Want Be clear about "what the gene is" and "what fitness should maximize." For a quantity you want to minimize (distance, cost), write "shortest" / "smallest" and the engine can handle it via sign-flipping. For a moving creature, adding "with an animation of the best individual too" gets you viewReset/viewStep.

11Modifying Code

Pressing ✏️ Modify Prompt copies a frame containing the current code and a modification instruction. Paste it into a generative AI, list what you want changed as bullet points, and you'll get the full modified code back. Select all in the code field, replace it, and press ▶ Apply.

Pressing 📖 Explain Prompt copies a prompt asking for an explanation of what kind of model the currently running code is (requesting an overview, algorithm description, and pseudocode). Pasting it into a generative AI gets you an explanation faithful to the implementation. Also, putting const TITLE = 'model name' in generated/modified code reflects it in the browser tab name, the "About This Model" heading, and the filename used by 💾 Save .js (e.g., Mass-Spring_Creature.js).

Tricks That Reduce Failures Even on Free Tiers The prompt keeps to a minimal spec and strongly instructs, at both the start and end, "output exactly one code block, in full, without abbreviation" (to reduce truncated output or stray explanatory text on free-tier/small models). In ✏️ Modify Prompt, [What you want changed] is placed at the end, so write your changes there as bullet points.
Tips for Modifying Don't change too much at once: one or two small changes at a time. It's safer to keep a copy with 💾 Save .js each time it works.

🤖 AI Generate: Connecting Directly to a Generative AI's API (LM Studio / Cloud)

Pressing the code bar's 🤖 AI Generate lets you connect directly to an OpenAI-compatible API to modify or create code. The returned code is automatically inserted into the code field (it isn't run until you press ▶ Apply). No copy-and-paste needed.

  • Local (LM Studio, etc.): start the local server and turn on "Enable CORS" in the server settings. The endpoint is http://localhost:1234 (no API key needed).
  • Cloud (OpenAI-compatible): e.g., OpenRouter https://openrouter.ai/api/v1, DeepInfra https://api.deepinfra.com/v1/openai, OpenAI https://api.openai.com/v1. Requires an API key (most are pay-as-you-go).
  • You can choose the model name via 🔄 Fetch List (manual entry also works). Settings are remembered in the browser.
If the Connection Fails "Failed to fetch" is usually caused by the server not running, CORS not being enabled, or a wrong URL. Try opening http://localhost:1234/v1/models directly in your browser to see if JSON comes back. For cloud services, the service itself must support CORS (OpenRouter and DeepInfra do).

① Function Optimization (Bit-String GA)

Decodes a 32-bit gene into two real numbers x, y and optimizes an evaluation function (by default, minimizing the Rastrigin function). Simply rewriting the return of fitness() freely changes the function to maximize or the evaluation condition. Individuals are shown as points on the x–y plane, with the best point highlighted.

What to observe: changing the mutation rate and selection pressure lets you compare how susceptibility to local optima and convergence speed change. A great entry point for learning the difference between bit and real-valued representations.

② Mass-Spring Creature (2D Virtual Creature)

Connects four point masses with springs (muscles) and rhythmically contracts the muscles to crawl along the ground. The gene is the layout of the point masses (8 values) and the amplitude/phase of each muscle (12 values). Distance traveled to the right is the fitness. The best individual's walk is shown animated.

What to observe: diverse locomotion strategies such as "hopping" and "crawling" emerge as generations pass. Change fitness to height to evolve jumping instead. Use the All Individuals view to compare walking-style variations.

③ Soft-Body Creature (Voxels)

Builds a body from a 5×5 grid of voxels and walks it by contracting actuators. The gene is morphology (each cell's type: empty, rigid, soft, horizontal actuator, vertical actuator) and control (each cell's phase φ), plus amplitude and frequency. All of it is normalized to 52 real numbers in 0–1, converted into morphology and phase by decode(). Only the largest connected component becomes the mass-spring body, and the distance traveled to the right is maximized.

What to observe: the highlight is that shape and motion evolve simultaneously. Switching to the All Individuals view lets you compare various body shapes' walking side by side. If evaluation is heavy, lower "Evaluation steps" or "Population size."

④ Knapsack Problem

Maximizes the total value of items packed without exceeding the weight limit (capacity). The gene is an inclusion bit per item. fitness is the total value if within capacity, with a penalty applied to the overage if it's exceeded. Item weights/values are fixed (generated at the top of the code).

What to observe: moving the Capacity slider shows how the optimal packing changes. The capacity gauge and item grid (included = green) make the contents of the solution clear at a glance.

⑤ Traveling Salesman Problem (TSP)

Searches for the shortest tour that visits every city once and returns to the start. Because it's represented via the random-key method (each city holds a real-valued key, visited in ascending order = a permutation), standard uniform crossover and Gaussian mutation work as-is, always yielding a valid tour. fitness is −(tour length). The best tour is drawn on the map.

What to observe: the initially tangled route straightens into a short, tidy one as generations pass. Increasing the number of cities makes it harder, changing how population size and selection pressure affect the outcome.

12Errors & Solutions

If an error occurs when you press ▶ Apply or while running, a red message appears in the code bar. The line number of the cause, that line's contents, and a beginner-friendly hint are shown, and the code field opens automatically. Unusable syntax such as class, document.*, fetch, etc. is detected before applying.

Message / SymptomWhat to Do
GENE is requiredDefine either GENE = { type:'bit'|'real', length:… } or randomGenome().
fitness() errorCheck the length of arrays referenced inside the evaluation function, and the return value of decode. Make sure it's not returning a non-number or NaN.
draw() errorCheck for typos in the drawing function, or branches for when state.best is missing.
... is not definedA typo in a variable name, or it's used before being defined.
Unexpected token …Check that () {} [] are matched, and that no commas or semicolons are missing.
Fitness isn't improvingRaise the mutation rate to widen the search / adjust selection pressure and elitism / increase population size. Try reducing the problem's scale.

13FAQ

Q. The sliders aren't showing up.
A. They won't show without PARAM_DEFS in the code. Ask a generative AI: "Add PARAM_DEFS. Include the GA parameters too, such as population size and mutation rate."

Q. No chart appears.
A. Without PLOT_DEFS, it defaults to a "best/average fitness" chart. If you want a custom chart, have it add PLOT_DEFS.

Q. Is it OK for fitness to be negative?
A. Yes. The engine only treats it as "higher is better," so returning −(length), as in TSP, is fine. You can even do things like displaying -bestFitness on the chart as "length."

Q. The best individual doesn't move (creature models).
A. Animation requires viewReset(best, params) and viewStep(view, params). Tell a generative AI "I want to see the best individual move every frame" and it will add them.

Q. In All Individuals mode, each individual is too small.
A. Lowering the Count slider to something like 9 makes them display larger (§5).

Q. Evaluation is heavy and slow.
A. Combine lowering "Population size," lowering "Evaluation steps" for creature models, raising "Draw skipping," and lowering the run speed.

Q. The code disappears when I close the browser.
A. There's no auto-save. Keep a file with 💾 Save .js, and load it next time with 📂 Open (keeping it in your generative AI's chat history also works).

📚References & Sources

These are the key original sources the built-in models draw on as subject matter. All code is this project's own independent implementation (for the Soft-Body Creature, the code takes inspiration from the ideas noted below, but is implemented independently).

  • Genetic algorithms (GA): Holland, J. H. (1975). Adaptation in Natural and Artificial Systems. University of Michigan Press. / Goldberg, D. E. (1989). Genetic Algorithms in Search, Optimization, and Machine Learning. Addison-Wesley.
  • Mass-Spring Creature (evolving virtual creatures): Sims, K. (1994). Evolving virtual creatures. SIGGRAPH '94, 15–22. The origin of evolving virtual creatures. Sims evolved three-dimensional creatures made of articulated blocks, together with their neural controllers; the model here is not a reimplementation of that work but a far simpler two-dimensional mass-spring system, written independently in the spirit of that line of research.
  • Soft-Body Creature (voxels): Bhatia, J., Jackson, H., Tian, Y., Xu, J., & Matusik, W. (2021). Evolution Gym: A large-scale benchmark for evolving soft robots. NeurIPS 2021. The idea of "evolving soft robots made of voxels" is drawn from Evolution Gym (MIT License); the code is independently implemented.
  • Knapsack problem / traveling salesman problem (TSP): Both are classic combinatorial optimization problems (see standard textbooks).
